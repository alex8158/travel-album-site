# 智能图片与视频处理系统项目需求文档

## 1. 项目背景

当前项目面向旅行相册、图片管理和视频素材整理场景，用户在旅行、拍摄、导入媒体文件后，经常会遇到以下问题：

1. 图片数量多，存在大量重复、连拍、相似角度照片。
2. 部分图片存在模糊、过曝、欠曝、偏色、构图差等问题。
3. 视频素材中存在抖动、黑场、误拍、重复片段、无意义长镜头。
4. 手动筛选图片和视频耗时较长，用户体验较差。
5. 单纯依赖大模型处理全部图片和视频，成本高、速度慢、稳定性不可控。
6. 现有项目需要在上传后自动完成基础处理，并在前端展示处理结果。

因此，本项目需要建设一套 **分层式智能媒体处理系统**：

- 第一层：使用传统代码和计算机视觉算法完成批量化、低成本、稳定的基础处理。
- 第二层：对筛选后的高质量内容进行自动增强。
- 第三层：对少量高价值图片或视频片段调用 AI 模型进行智能判断、精修和剪辑决策。

项目目标不是一开始就完全依赖大模型，而是采用 **传统算法优先、模型按需介入** 的工程架构。

---

## 2. 项目目标

### 2.1 总体目标

构建一套可自动处理图片和视频的系统，实现媒体上传后的自动筛选、去重、模糊检测、质量评估、基础增强、智能剪辑和可选 AI 精修能力。

系统应能够：

1. 自动识别重复图片和相似图片。
2. 自动识别模糊、过曝、欠曝、严重偏色等低质量图片。
3. 自动从相似图片组中选出最佳图片。
4. 对保留图片进行一键基础增强。
5. 对高价值图片支持 AI 精修，例如去路人、去杂物、改善天空、修复局部问题。
6. 自动分析视频素材，完成切镜头、废片识别、抖动检测、模糊检测和片段筛选。
7. 对保留视频片段进行基础优化，例如转码、防抖、亮度调整、音频归一化。
8. 支持 AI 模型参与视频内容理解和智能剪辑决策。
9. 前端能够清楚展示处理状态、处理结果、保留原因和删除建议。
10. 系统处理过程应稳定、可恢复、可追踪，避免任务中断导致数据状态混乱。

---

## 3. 设计原则

### 3.1 传统算法优先

对于明确、规则化、可批量处理的问题，优先使用传统代码和计算机视觉算法。

适合传统算法处理的任务包括：

- 文件去重
- 相似图片聚类
- 模糊检测
- 曝光检测
- 色偏检测
- 图片缩略图生成
- 视频转码
- 视频抽帧
- 视频镜头切分
- 视频黑场检测
- 视频抖动检测
- 音频音量分析

### 3.2 大模型按需介入

大模型只用于传统算法难以稳定解决的场景。

适合模型处理的任务包括：

- 图片语义判断
- 图片审美排序
- 高价值图片精修
- 复杂场景识别
- 视频内容理解
- 视频高光片段选择
- 视频剪辑方案生成
- 标题、字幕、旁白、摘要生成

### 3.3 分阶段处理

系统不得在上传后一次性进行所有高成本处理，应采用分阶段流水线：

1. 导入阶段
2. 基础分析阶段
3. 去重和质量筛选阶段
4. 自动增强阶段
5. AI 精修或智能剪辑阶段
6. 前端展示与人工确认阶段

### 3.4 可回滚、可追踪

每个处理步骤都需要记录状态、结果、耗时和错误信息。

系统应支持：

- 失败重试
- 单张图片重新处理
- 单个视频重新处理
- 单个处理阶段重新执行
- 查看处理日志
- 保留原始文件
- 不直接覆盖原图和原视频

## 6. 图片处理需求

## 6.1 图片上传

### 需求说明

用户可以上传单张或多张图片，系统应保存原始文件，并生成处理任务。

### 功能要求

1. 支持 JPG、JPEG、PNG、HEIC、WEBP 等常见格式。
2. 上传后保留原始文件。
3. 生成缩略图用于前端预览。
4. 自动读取 EXIF 信息。
5. 自动记录图片来源、上传时间、文件大小、分辨率、拍摄时间、相机型号等信息。
6. 上传完成后自动进入图片处理队列。

### 验收标准

1. 用户上传图片后，前端可以看到缩略图。
2. 系统可以显示图片上传状态。
3. 图片原始文件不会被覆盖。
4. 上传失败时需要显示明确错误信息。
5. 上传成功后自动创建处理任务。

---

## 6.2 图片去重

### 需求说明

系统需要识别完全重复图片和高度相似图片，减少重复展示和重复存储。

### 处理方式

图片去重分为两类：

1. 完全重复：
   - 使用 MD5 / SHA256 文件 hash 判断。
2. 近似重复：
   - 使用 pHash / dHash 判断。
   - 使用 DINOv2 / CLIP embedding 判断语义和视觉相似度。
   - 使用 FAISS 进行向量相似检索。

### 功能要求

1. 上传后自动计算文件 hash。
2. 对完全相同文件标记为重复。
3. 对相似图片进行分组。
4. 每个重复组中推荐一张最佳图片。
5. 前端展示重复组。
6. 用户可以查看每组内所有图片。
7. 用户可以手动修改保留图片。

### 验收标准

1. 完全相同图片可以被识别。
2. 连拍图片可以被归入同一组。
3. 系统不会直接删除重复图片，只给出推荐。
4. 用户可以手动恢复或保留任意图片。
5. 每个重复组有明确的推荐保留结果。

---

## 6.3 图片模糊检测

### 需求说明

系统需要自动识别模糊图片，避免低质量图片进入最终相册。

### 处理方式

优先使用传统图像算法，例如：

1. Laplacian variance。
2. Tenengrad 清晰度评分。
3. 局部对比度分析。
4. 人脸区域清晰度检测。
5. 主体区域清晰度检测。

### 功能要求

1. 自动计算图片清晰度分数。
2. 根据阈值标记图片为清晰、疑似模糊、严重模糊。
3. 对人像图片优先判断人脸区域是否清晰。
4. 对风景图片判断整体清晰度。
5. 前端展示模糊评分和建议。

### 验收标准

1. 严重虚焦图片可以被识别。
2. 明显抖动图片可以被识别。
3. 系统允许用户手动保留被标记为模糊的图片。
4. 模糊检测结果需要记录在数据库中。
5. 模糊检测失败时不影响其他图片处理。

---

## 6.4 图片曝光和色彩检测

### 需求说明

系统需要识别明显过曝、欠曝、偏色的图片，为后续自动增强提供依据。

### 功能要求

1. 计算图片亮度分布。
2. 判断是否过曝。
3. 判断是否欠曝。
4. 判断是否存在明显偏色。
5. 记录曝光评分。
6. 记录色彩评分。
7. 为自动增强提供参数参考。

### 验收标准

1. 明显过暗图片可以被标记。
2. 明显过亮图片可以被标记。
3. 明显偏蓝、偏黄、偏绿图片可以被标记。
4. 处理结果可在前端查看。
5. 处理结果可用于后续增强流程。

---

## 6.5 图片质量评分

### 需求说明

系统需要给每张图片生成综合质量评分，用于排序和推荐保留。

### 评分维度

图片质量评分包括：

1. 清晰度。
2. 曝光。
3. 色彩。
4. 噪点。
5. 构图。
6. 主体完整性。
7. 人脸质量。
8. 美学评分。
9. 是否重复。
10. 是否存在明显瑕疵。

### 功能要求

1. 系统生成 0 到 100 的综合质量评分。
2. 每个评分维度应单独记录。
3. 综合评分应支持后续调整权重。
4. 重复组内按照质量评分排序。
5. 前端展示推荐保留理由。

### 验收标准

1. 同一重复组中更清晰、曝光更正常的图片应优先推荐。
2. 评分结果需要可解释。
3. 用户可以看到系统为什么推荐保留某张图片。
4. 评分结果可以被重新计算。
5. 评分逻辑支持后续调参。

---

## 6.6 图片自动增强

### 需求说明

系统需要对保留下来的图片执行基础自动增强，类似修图软件的一键处理。

### 处理内容

自动增强包括：

1. 自动白平衡。
2. 自动曝光调整。
3. 自动对比度调整。
4. 自动色彩校正。
5. 轻度锐化。
6. 轻度降噪。
7. 自动拉直。
8. 自动裁切建议。

### 设计要求

自动增强优先使用传统图像处理算法，不默认调用大模型。

### 功能要求

1. 只对推荐保留图片执行自动增强。
2. 增强结果保存为新文件。
3. 原图必须保留。
4. 前端支持原图和增强图对比。
5. 用户可以选择使用原图或增强图。
6. 用户可以重新执行增强。

### 验收标准

1. 自动增强不会覆盖原始图片。
2. 增强后图片自然，不应过度锐化或过度饱和。
3. 用户可以回退到原图。
4. 增强任务失败不影响原图展示。
5. 增强结果可以被前端预览。

---

## 6.7 图片 AI 精修

### 需求说明

AI 精修不是默认处理流程，只对用户主动选择或系统识别为高价值的图片执行。

### 适用场景

AI 精修适用于：

1. 去除背景路人。
2. 去除画面杂物。
3. 修复天空细节。
4. 修复局部阴影。
5. 水下照片偏色修正。
6. 人像局部优化。
7. 复杂场景色彩优化。
8. 智能裁切和构图优化。
9. 高价值照片审美增强。

### 功能要求

1. 用户可以在前端点击“AI 精修”。
2. 系统应显示 AI 精修会消耗更多时间和成本。
3. AI 精修结果保存为新版本。
4. 支持原图、自动增强图、AI 精修图对比。
5. 支持用户放弃 AI 精修结果。
6. 支持记录模型名称、请求参数、处理时间和处理结果。

### 验收标准

1. AI 精修不会覆盖原图。
2. 用户可以选择是否采用精修版本。
3. AI 精修失败时需要显示失败原因。
4. 系统可以限制单个用户每日 AI 精修次数。
5. 系统可以配置是否启用 AI 精修功能。

# 7. 视频处理需求

## 7.1 视频上传

### 需求说明

用户可以上传视频文件，系统保存原始视频，并生成视频处理任务。

### 功能要求

1. 支持 MP4、MOV、M4V、AVI、MKV 等常见格式。
2. 上传后保留原始视频。
3. 使用 ffprobe 读取视频元信息。
4. 记录视频时长、分辨率、帧率、码率、编码格式、音频格式。
5. 生成视频封面图。
6. 生成低清代理文件用于前端预览。
7. 上传成功后进入视频处理队列。

### 验收标准

1. 用户上传视频后可以在前端预览。
2. 系统可以显示视频基础信息。
3. 原始视频不会被覆盖。
4. 视频处理失败不会影响原始视频保存。
5. 视频上传状态和处理状态可追踪。

---

## 7.2 视频镜头切分

### 需求说明

系统需要将长视频自动切分为多个镜头片段，便于后续筛选和剪辑。

### 处理方式

优先使用传统算法：

1. PySceneDetect。
2. FFmpeg scene detection。
3. 基于画面差异的镜头检测。
4. 基于关键帧的片段划分。

### 功能要求

1. 自动识别镜头切换点。
2. 生成视频片段列表。
3. 每个片段记录开始时间、结束时间、时长。
4. 为每个片段生成缩略图。
5. 为每个片段计算基础质量评分。

### 验收标准

1. 长视频可以被切分为多个片段。
2. 每个片段可以单独预览。
3. 片段时间点准确。
4. 切分失败时系统可以退回到固定时间切片方案。
5. 前端可以展示片段列表。

---

## 7.3 视频废片识别

### 需求说明

系统需要自动识别明显无价值的视频片段。

### 废片类型

废片包括：

1. 黑屏片段。
2. 镜头盖遮挡。
3. 长时间拍地面。
4. 长时间拍天空但无主体。
5. 严重抖动片段。
6. 严重模糊片段。
7. 误触录制片段。
8. 重复拍摄片段。
9. 音频异常片段。
10. 过短且无有效内容片段。

### 功能要求

1. 自动分析每个视频片段。
2. 标记废片类型。
3. 生成废片评分。
4. 系统只给出删除建议，不直接删除。
5. 用户可以手动恢复片段。

### 验收标准

1. 明显黑屏片段可以被识别。
2. 明显严重抖动片段可以被识别。
3. 明显无意义片段可以被标记。
4. 用户可以查看废片原因。
5. 用户可以手动保留任意片段。

---

## 7.4 视频模糊和抖动检测

### 需求说明

系统需要自动判断视频片段是否清晰、稳定。

### 处理方式

1. 从视频片段中抽取关键帧。
2. 对关键帧执行模糊检测。
3. 计算连续帧之间的运动变化。
4. 判断是否存在严重抖动。
5. 结合片段时长生成稳定性评分。

### 功能要求

1. 为每个视频片段生成清晰度评分。
2. 为每个视频片段生成稳定性评分。
3. 标记严重模糊片段。
4. 标记严重抖动片段。
5. 处理结果用于后续剪辑筛选。

### 验收标准

1. 模糊视频片段可以被识别。
2. 抖动严重的视频片段可以被识别。
3. 稳定片段可以被优先推荐。
4. 检测结果可以在前端查看。
5. 检测结果可以被重新计算。

---

## 7.5 视频基础优化

### 需求说明

系统需要对保留的视频片段执行基础优化处理。

### 处理内容

视频基础优化包括：

1. 转码。
2. 分辨率统一。
3. 帧率统一。
4. 轻度防抖。
5. 亮度调整。
6. 对比度调整。
7. 色彩修正。
8. 音量归一化。
9. 去除黑边。
10. 生成预览版本。

### 设计要求

视频基础优化优先使用 FFmpeg 和传统视频处理工具，不默认调用大模型。

### 功能要求

1. 只对候选保留片段执行优化。
2. 优化结果保存为新文件。
3. 原视频必须保留。
4. 用户可以预览优化前后效果。
5. 用户可以选择是否采用优化版本。

### 验收标准

1. 优化不会覆盖原视频。
2. 视频可以正常播放。
3. 优化后画面不应明显失真。
4. 音画同步不能被破坏。
5. 处理失败时可回退到原始片段。

---

## 7.6 视频智能剪辑

### 需求说明

视频智能剪辑用于将筛选后的候选片段自动组合成短视频。

### 剪辑目标

系统应支持生成以下版本：

1. 30 秒快速预览版。
2. 1 分钟旅行短片版。
3. 3 到 5 分钟完整回顾版。
4. 用户自定义时长版本。

### 处理方式

视频智能剪辑分为两层：

1. 传统算法负责：
   - 切片
   - 筛选
   - 转码
   - 拼接
   - 音频处理
   - 字幕烧录
2. AI 模型负责：
   - 内容理解
   - 高光选择
   - 片段排序
   - 剪辑节奏建议
   - 标题生成
   - 字幕文案生成
   - 旁白生成

### 功能要求

1. 系统根据候选片段生成剪辑方案。
2. 剪辑方案包括片段顺序、起止时间、保留原因。
3. 用户可以预览剪辑方案。
4. 用户可以手动调整片段顺序。
5. 用户可以选择生成短视频。
6. 系统使用 FFmpeg 执行最终合成。
7. 生成后的视频应保存为新文件。

### 验收标准

1. 系统可以从多个片段生成短视频。
2. 生成视频可以正常播放。
3. 用户可以查看每个片段被选中的原因。
4. 用户可以重新生成不同长度版本。
5. AI 剪辑失败时，可以使用传统规则生成基础剪辑版本。

# 11. 处理流程设计

## 11.1 图片处理流程

图片上传后的完整流程如下：

1. 用户上传图片。
2. 后端保存原图。
3. 创建图片处理任务。
4. Worker 生成缩略图。
5. Worker 读取 EXIF。
6. Worker 计算文件 hash。
7. Worker 判断完全重复。
8. Worker 计算 pHash / dHash。
9. Worker 提取 embedding。
10. Worker 执行相似图片分组。
11. Worker 执行模糊检测。
12. Worker 执行曝光和色彩检测。
13. Worker 生成综合质量评分。
14. 系统在重复组内推荐最佳图片。
15. 对推荐保留图片执行自动增强。
16. 前端展示处理结果。
17. 用户确认保留、删除、恢复或 AI 精修。

---

## 11.2 视频处理流程

视频上传后的完整流程如下：

1. 用户上传视频。
2. 后端保存原视频。
3. 创建视频处理任务。
4. Worker 使用 ffprobe 读取视频信息。
5. Worker 生成封面图。
6. Worker 生成低清代理视频。
7. Worker 抽取关键帧。
8. Worker 执行镜头切分。
9. Worker 分析每个片段的清晰度。
10. Worker 分析每个片段的稳定性。
11. Worker 检测黑场、废片和重复片段。
12. 系统生成候选保留片段。
13. 对候选片段执行基础优化。
14. 用户查看片段列表。
15. 用户选择是否生成短视频。
16. 系统调用 AI 生成剪辑方案。
17. Worker 使用 FFmpeg 合成最终视频。
18. 前端展示最终结果。

# 14. 非功能需求

## 14.1 性能要求

1. 图片上传后应尽快生成缩略图。
2. 图片基础分析应支持批量处理。
3. 视频处理应异步执行，不阻塞前端。
4. 前端不得长时间等待单个请求返回。
5. 所有耗时任务必须走任务队列。
6. 大模型调用必须限制并发。
7. 视频处理必须支持低清代理文件，避免前端加载原视频。

---

## 14.2 稳定性要求

1. 任意单个媒体处理失败不能影响整个相册。
2. Worker 异常退出后任务可以恢复。
3. 任务状态必须准确记录。
4. 数据库写入需要避免部分成功、部分失败导致状态混乱。
5. 删除媒体时必须先删除关联关系，再删除主记录，避免外键错误。
6. 原始文件不得被处理流程覆盖。

---

## 14.3 成本控制要求

1. 默认不对全部媒体调用大模型。
2. AI 精修需要用户主动触发或系统明确标记高价值。
3. 视频 AI 分析只处理候选片段，不处理所有原始长视频。
4. 模型调用需要记录 token、耗时、费用估算。
5. 支持配置每日 AI 调用上限。
6. 支持按用户或相册限制 AI 精修次数。

---

## 14.4 可维护性要求

1. 图片处理、视频处理、AI 处理应拆分为独立模块。
2. 每个处理步骤应有单独函数。
3. 每个 Worker 应有清晰日志。
4. 阈值需要集中配置。
5. 模型调用需要封装成独立服务。
6. 后续可以替换模型供应商。

---

## 14.5 用户体验要求

1. 前端应展示清晰的处理进度。
2. 不应让用户等待整个任务完成后才能浏览图片。
3. 已完成处理的媒体应优先展示。
4. 失败任务应给出可理解的错误信息。
5. 删除操作应支持撤销或恢复。
6. 推荐删除的图片和视频片段不得自动永久删除。

---

## 15.2 图片处理

建议使用：

- sharp：缩略图、格式转换、基础增强。
- OpenCV：模糊检测、曝光检测、图像分析。
- image-hash：pHash / dHash。
- Python + DINOv2 / CLIP：高级相似度和语义特征。
- FAISS：向量检索和相似图片聚类。

## 15.3 视频处理

建议使用：

- FFmpeg：转码、抽帧、拼接、音频处理。
- ffprobe：视频元数据读取。
- PySceneDetect：镜头切分。
- OpenCV：关键帧模糊和抖动分析。
- Whisper 或其他 ASR：后续字幕识别。

## 15.4 AI 模型

建议按用途选择：

- 图片理解：Gemini / GPT 多模态模型。
- 图片精修：GPT Image / 其他图像编辑模型。
- 视频理解：Gemini 视频理解模型。
- 视频生成或改画面：Veo / Runway / 可替换视频模型。
- 工程总控和代码开发：GPT 或 Claude。

# 18. 风险与控制措施

## 18.1 模糊检测误判

风险：

- 夜景、低光、高 ISO 图片可能被误判为模糊。
- 背景虚化人像可能被误判为模糊。

控制措施：

1. 不自动永久删除。
2. 给出“疑似模糊”而非直接删除。
3. 对人像优先检测人脸区域。
4. 支持用户手动保留。
5. 支持阈值调整。

---

## 18.2 相似图片误分组

风险：

- 同一景点不同角度可能被归为重复。
- 同一人物不同动作可能被归为重复。

控制措施：

1. 同时使用 hash 和 embedding。
2. 分组只做推荐，不直接删除。
3. 前端展示整组图片。
4. 用户可以手动选择保留。
5. 对低置信度分组标记为“疑似重复”。

---

## 18.3 AI 成本过高

风险：

- 如果对所有媒体调用 AI，成本和处理时间会快速增加。

控制措施：

1. 默认不全量调用 AI。
2. AI 只处理候选内容。
3. 设置每日调用上限。
4. 记录调用费用。
5. 用户主动触发 AI 精修。

---

## 18.4 视频处理耗时过长

风险：

- 长视频转码、抽帧、切片会消耗大量 CPU 和磁盘。

控制措施：

1. 使用异步任务队列。
2. 先生成低清代理文件。
3. 控制并发数量。
4. 长视频分段处理。
5. 支持任务暂停和重试。

---

## 18.5 数据状态不一致

风险：

- 处理任务失败后，数据库状态和文件状态可能不一致。

控制措施：

1. 每一步处理结果单独记录。
2. 使用任务状态机。
3. 数据库写入使用事务。
4. 删除媒体前先删除关联数据。
5. 保留失败日志。
6. 支持重新处理。

---

# 19. 推荐最终架构总结

本项目推荐采用以下架构：

图片处理：

导入图片  
→ 生成缩略图  
→ 读取 EXIF  
→ 文件 hash 去重  
→ pHash / dHash 近似去重  
→ DINOv2 / CLIP 相似度聚类  
→ 模糊检测  
→ 曝光和色彩检测  
→ 综合质量评分  
→ 推荐保留最佳图片  
→ 一键自动增强  
→ 用户按需 AI 精修  

视频处理：

导入视频  
→ 读取元信息  
→ 生成封面和代理视频  
→ 抽取关键帧  
→ 镜头切分  
→ 模糊检测  
→ 抖动检测  
→ 黑场和废片识别  
→ 生成候选片段  
→ 基础优化  
→ AI 生成剪辑方案  
→ FFmpeg 合成最终短视频  

核心原则：

1. 传统算法处理大批量基础任务。
2. AI 模型只处理高价值和复杂判断任务。
3. 原始文件永远保留。
4. 所有处理结果生成新版本。
5. 系统只做推荐，不自动永久删除。
6. 所有任务异步执行。
7. 前端持续展示处理状态。
8. 支持失败重试和人工干预。
